## 一、按 v0.82 文档落地的四处

### 1. PauseManager：谁来恢复时间

上一版各处直接调 `TimeManager.pause_for()`，谁都能停，但没人负责恢复。两个原因叠加时（赛事周恰好又弹了事件），先处理完的那个会把时间放走，另一个原因还在，玩家就看到时间在弹窗背后偷偷跑。

改成「原因集合」：

```gdscript
PauseManager.request("event")    // 入集合 + 立刻降到 0 档
PauseManager.release("event")    // 只移除自己那条
```

规则是：**全部原因解除后也不自动开动**，只是广播状态，等玩家自己点「跑」。避免时间突然跑起来把玩家吓一跳。

已接入三种原因：`event`（随机事件）、`stamina`（体力见底）、`tourney`（赛事周）。

### 2. 排程编辑 UI

「本周计划」卡片，7 行对应周一到周日：

```
本周计划                      点一下换
周一   ●                    技术训练
周二                        技术训练
周三                        体能训练
周四                        技术训练
周五                        体能训练
周六                          休息
周日                        文化课
```

当天那行有红点、按钮实心。点任意一行弹出六选一（技术/体能/心理/战术/休息/文化课），选完立即写回 `p.schedule[i]`，下一次时间流就按新表走。

### 3. 赛事接入时间流

发现一个更严重的问题：**不主动报名就永远不比赛**。用 fuzz 跑 2000 天，金钱还是 0——时间流可以一直空转，没有任何收入和声望。

现在每周一检查：

- 已报名且未打完 → 暂停，提示「该上场了」
- 未报名但有可报名赛事 → 暂停，提示「本周有 N 站赛事可报名。不打比赛就没有收入」
- 每周只提示一次（记在 `record["tourney_prompt"]`），玩家点「跑」即视为跳过

### 4. 器材页 6px 溢出

文档说是 ScrollBar 最小尺寸算错。按那个方向改了 `VScrollBar` 的 `scroll` stylebox 负边距——**没用，数值一点没变**。

真因是器材描述那一行：

```gdscript
UIKit.dim("%s · %s" % [_gear_stats(it), it.d], 10)
```

`Label` 不换行，长描述直接把父容器的最小宽度顶到 411px，整页跟着变宽。竖屏加 `text_overrun_behavior` + `clip_text` 后归零。

> 结论：文档给的方案方向错了。这类问题的排查顺序应该是「先找谁的最小宽度最大」，而不是「先怀疑滚动条」。

## 四、没做的（诚实清单）

1. **连锁事件**（脚踝扭伤 → 继续高强度 → 跟腱撕裂）。需要 EventBus 支持延迟投递 + 可取消的 timer，是个独立小系统，这轮没动。
2. **教练谈话 / 升学审批自动暂停**。PauseManager 已经备好 `coach` / `breaking` 两个原因位，但没有触发点——游戏里还没有这两类事件。
3. **赛事备战模式**（自动把训练替换成战术演练）。
4. **后台切回的无缝续播**：`_can_flow()` 在失焦时会因为 `pending_event` 之类停住，但没有做「记录离开时间、回来补算」的逻辑。iOS 上切后台再回来不会跳时间，这点是安全的，但也谈不上无缝。
